# Instructions for agents working in this repository

This repository holds the manuscript of a technical report on dokploy-iac and the harness that
produces and checks every number in it. Reviewers will rerun the harness, so provenance matters more
than speed.

## Layout

- `paper/`: the manuscript (`sections/`, `outline.md`, `references.bib`). `paper/tables/` and
  `paper/figures/` are generated by `declarative-iac report` and never edited by hand.
- `src/declarative_iac/`: the harness. `core/` holds domain-free utilities, `domain/` one package per
  bounded context (provenance, static, claims, developer, live, report), `workflow/` the CLI commands
  that coordinate them. The design is in `docs/harness/DESIGN.md`.
- `config/`: the pinned snapshot (`snapshot.yaml`) and the scenario data of the live experiments.
- `claims/claims.yaml`: every quantitative statement in the paper and the result that supports it.
- `evaluation/`: the pre-registration and its deviations log.
- `results/`: committed outputs, each directory with a `manifest.json`.

## Commands

- `uv sync --dev` installs everything from `uv.lock`; `uv run declarative-iac --help` lists commands.
- `uv run ruff check . && uv run ruff format --check . && uv run pyright && uv run pytest` must pass.
- Use `uv add` / `uv remove` for dependencies; never `pip`.

## Rules

1. **Never modify the system under study, and never import its code.** Read it with
   `Snapshot.show()` (`git show <commit>:<path>`) and run its binary as a black box.
2. **Every number traces to a manifest.** Experiments write outputs plus `manifest.json`. Do not edit
   files under `results/` or `paper/tables/` by hand; rerun the command instead.
3. **Every number in the paper is a claim.** Add or change it in `claims/claims.yaml` together with the
   prose, and keep `claims verify` and `claims check-paper` passing.
4. **Pre-registration first.** Once `evaluation/PREREGISTRATION.md` is tagged `prereg-v1`, change
   hypotheses, scenarios, operators or analysis only through `evaluation/DEVIATIONS.md`.
5. **Oracles are independent.** Live oracles are written from Dokploy responses, not from the
   system's specifications or code. The observer is read-only.
6. **Two tiers of evidence.** Results from the system's own tests are `developer` evidence; results
   from this harness are `independent`. Never mix them in one table without labels.
7. **Live runs use disposable local instances only.** Never commit `DOKPLOY_URL`, API keys or
   fingerprint keys.

## Writing the paper

1. **Describe the final design only.** No development history, and no earlier engine.
2. **Describe what the code does** at tag `eval-B1`; where design documents and code disagree, the
   paper follows the code.
3. **Do not invent values.** Mark gaps as `[RESULT: ...]` or `[TODO: ...]`.
4. **Citations** are inline Markdown links, `[Author Year](https://doi.org/...)`, with every DOI
   verified and added to `paper/references.bib`. The abstract has no citations.
5. **One section at a time**; update the status in `paper/outline.md`.

Use the skills in `.agents/skills/`: `science-research-writing` for prose, and
`responsibility-driven-design` / `domain-driven-design` for harness design.
